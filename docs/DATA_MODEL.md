# Data model

42 tables in a single SQL Server database. All timestamps are UTC. All primary keys are
`Guid` generated in the entity constructor, so an entity has a stable identity before it is
saved.

## 1. Base entity

`Domain/Common/Entity.cs`

```csharp
public abstract class Entity
{
    public Guid Id { get; set; } = Guid.NewGuid();
    public DateTime CreatedAtUtc { get; set; } = DateTime.UtcNow;
    public DateTime UpdatedAtUtc { get; set; } = DateTime.UtcNow;
    public byte[] RowVersion { get; set; } = Array.Empty<byte>();
    public void Touch() => UpdatedAtUtc = DateTime.UtcNow;
}
```

`RowVersion` is an EF Core concurrency token. `Touch()` must be called before saving a
mutation so `UpdatedAtUtc` is accurate.

`IWorkspaceScoped` marks entities that carry a `WorkspaceId`. Every query that serves the UI
filters on it.

## 2. Research core

### `ResearchWorkspace`

The top-level container. Everything else hangs off a workspace.

| Property | Type | Default | Notes |
| --- | --- | --- | --- |
| `Name` | string | required | Display name |
| `Slug` | string | required | URL-safe identifier |
| `Description` | string? | null | |
| `Objective` | string? | null | The research question |
| `AccentColor` | string | `#22D3EE` | Per-workspace UI accent |
| `IsArchived` | bool | false | Archived workspaces are hidden by default |
| `AiInstructions` | string? | null | Prepended to companion prompts |
| `PreferredLanguage` | string | `fa-IR` | |
| `DataRoute` | `DataRoute` | `LocalOnly` | **Security-relevant** — see below |
| `AllowCrossWorkspaceAccess` | bool | false | Opt-in to cross-workspace retrieval |

`DataRoute` is the single most important field in the schema. `LocalOnly` means no
`CloudAllowed` provider may ever serve this workspace. The check lives in
`AiProviderResolver.FindConfigurationAsync` and cannot be bypassed by a caller.

### `ResearchQuestion`

Follow-up questions, either user-authored or generated by the research engine when a
question had no supporting evidence. `IsAiGenerated` distinguishes them.

### `ResearchRun` and `ResearchPlanStep`

A run is a research objective with a nine-step plan. `ResearchRunStatus` moves
`Draft → AwaitingApproval → Running → Completed | Cancelled | Failed`. Execution requires
explicit approval, so a plan can be inspected before it costs anything.

`ResearchPlanStepKind` is a fixed enum: `ClarifyObjective`, `DecomposeQuestions`,
`InventoryKnowledge`, `RetrieveEvidence`, `EvaluateEvidence`, `DetectContradictions`,
`FollowUpQuestions`, `Synthesize`, `DraftReport`.

### `ResearchFinding`

A statement produced by a run, carrying `EpistemicStatus`, `EvidenceChunkIds`, and `Caveat`.
`EvidenceChunkIds` is stored as a serialized list and rendered verbatim in the UI so a
finding can always be traced back to specific passages.

### `ResearchNote`, `ResearchTimelineEvent`

Free-form notes, and the append-only activity log that powers `/timeline`.

## 3. Sources and documents

### `Source` and `SourceVersion`

A `Source` is the logical document (title, author, publisher, URL, language, tags,
reliability rating). A `SourceVersion` is one ingested revision with its own extraction
status, page count, character count, and `ProcessingError`.

Versioning exists so reprocessing a file does not destroy the previous extraction. The
`Source` points at `LatestVersionId`.

`SourceKind`: `Pdf`, `Docx`, `Text`, `Markdown`, `Html`, `Csv`, `Json`, `Image`, `WebPage`,
`ManualNote`, `StructuredImport`.

### `Document`, `DocumentPage`, `DocumentChunk`

`Document` is the extracted representation of a `SourceVersion`. `DocumentPage` holds the
text of one page plus `OcrApplied`. `DocumentChunk` holds a retrieval-sized slice with
`PageNumber`, `ChunkIndex`, `StartOffset`, `EndOffset`, `Text`, and `TokenEstimate`.

Offsets are preserved so the reader can highlight the exact span a citation refers to.

### `DocumentAnnotation`, `DocumentBookmark`

User highlights and reading positions.

## 4. Retrieval indexes

### `ChunkTerm` — the lexical inverted index

| Column | Purpose |
| --- | --- |
| `DocumentChunkId` | Which chunk contains the term |
| `WorkspaceId` | Denormalised so lexical search filters without a join |
| `Term` | Normalized token |
| `Frequency` | Occurrences in that chunk |

**Why a maintained index instead of SQL Server full-text search:** SQL Server 2019 ships
English and Arabic word breakers only. Persian text is not segmented correctly by either, so
`CONTAINS`/`FREETEXT` produce poor recall on Persian. A maintained inverted index built by
`PersianEnglishTokenizer` gives correct Persian tokenization and is fast enough for a
personal corpus. See `docs/RETRIEVAL.md`.

### `ChunkEmbedding` — the vector store

| Column | Purpose |
| --- | --- |
| `DocumentChunkId` | One embedding per chunk |
| `WorkspaceId` | Filter without a join |
| `Dimensions` | Vector length, used to skip mismatched models |
| `Vector` | Packed float32 `varbinary` |

`ChunkEmbedding.Pack(float[])` / `Unpack(byte[])` convert between `float[]` and a byte blob.
SQL Server 2019 has no `VECTOR` type, so similarity is computed in-process. See
`docs/VECTOR_STORAGE.md`.

## 5. Claims and evidence

### `Claim`

A statement under review.

| Property | Notes |
| --- | --- |
| `Statement` | The claim text |
| `ClaimType` | `Factual`, `Statistical`, `Causal`, `Predictive`, `Interpretive`, `Normative`, `Hypothetical` |
| `Status` | `Unreviewed`, `Supported`, `PartiallySupported`, `Contested`, `Contradicted`, `Outdated`, `Unverifiable` |
| `EpistemicStatus` | `Verified`, `SourceReported`, `AiInterpretation`, `LogicalInference`, `Hypothesis`, `Unknown` |
| `SourceId`, `DocumentChunkId`, `PageNumber`, `SourceExcerpt` | Provenance |
| `TemporalContext` | When the claim applies |
| `IsAiExtracted` | Honest provenance flag |
| `UserAnnotation` | Reviewer note |
| `VerifiedAtUtc` | Set only by the promotion path |

**The only path that changes `Status` is `ClaimsService.SetStatusAsync`.** Setting
`Supported` promotes `EpistemicStatus` to `Verified` and stamps `VerifiedAtUtc`. Nothing else
may write those fields — that is what makes "verified" mean something.

### `ClaimEvidence`

Links a claim to a chunk with a `Stance` (`Supports`, `PartiallySupports`, `Neutral`,
`PartiallyContradicts`, `Contradicts`), an `Excerpt`, a `Rationale`, and `IsAiGenerated`.

### `ClaimConflict`

Records that two claims disagree, with an `Explanation`, `IsResolved`, and `Resolution`.
`ClaimAId` and `ClaimBId` are explicit columns, not a self-referencing navigation, so the
pair is unambiguous.

## 6. Knowledge graph

### `KnowledgeNode`

`Kind` is one of `Concept`, `Person`, `Organization`, `Technology`, `Event`, `Document`,
`Claim`, `ResearchQuestion`, `Topic`. `IsUserConfirmed` distinguishes a human assertion from
an unconfirmed suggestion. `SourceCount` tracks how many sources mention it.

### `KnowledgeRelationship`

`Kind` is one of `Supports`, `Contradicts`, `DependsOn`, `RelatedTo`, `DerivedFrom`,
`Mentions`, `Explains`, `Causes`. Carries `IsUserConfirmed` and `IsAiSuggested` separately,
because "a human confirmed it" and "a model proposed it" are different facts.

### `KnowledgeRelationshipEvidence`

Join table linking a relationship to the chunks that justify it.

---

## 7. Reports

### `ResearchReport` and `ResearchReportVersion`

A report is a title, a template (`technical`, `executive`, `literature`, `comparison`), and
an ordered list of versions. Each version stores `Markdown`, `CitationsJson`, and a
`ChangeNote`. Versions are never mutated — adding a version appends.

The property is named **`Markdown`**, not `MarkdownBody`.

---

## 8. Learning

### `LearningPath`, `LearningTopic`

A path is a title plus an objective; topics are ordered by `SortOrder`.

### `Flashcard`, `FlashcardReview`

`Flashcard` holds `Front`, `Back`, `Repetitions`, `IntervalDays`, `EaseFactor`, `DueAtUtc`.
`FlashcardReview` is the immutable log of each review.

Scheduling is SM-2: quality below 3 resets `Repetitions` to 0 and `IntervalDays` to 1; the
ease factor has a floor of 1.3.

### `Quiz`, `QuizQuestion`, `QuizAttempt`

`QuizQuestion` stores `OptionsJson`, `CorrectOptionIndex`, `ExpectedAnswer`, `Explanation`,
and an optional `DocumentChunkId` linking the question to its source passage.

## 9. AI

### `AiProvider`

| Property | Notes |
| --- | --- |
| `Name` | Display name |
| `Kind` | `OpenAiCompatible`, `Ollama`, `AzureOpenAi`, `DeterministicFake` |
| `BaseUrl` | Endpoint root |
| `ApiKeySecretName` | **A reference only.** The key itself is never in the database |
| `IsEnabled` | Disabled providers are skipped by the resolver |
| `DataRoute` | `LocalOnly` or `CloudAllowed` |
| `LastValidatedAtUtc`, `LastValidationResult` | Last connectivity check |

### `AiModelConfiguration`

`Capability` (`Chat`, `Embedding`, `Reranking`, `Ocr`, `Transcription`), `ModelName`,
`Temperature` (0.2), `MaxOutputTokens` (2048), `ContextWindow` (8192), `TimeoutSeconds` (120),
`MaxRetries` (2), `Dimensions` (0 for non-embedding), `IsDefault`.

Exactly one default per capability is maintained by `SettingsService.ClearDefaultAsync`.

### `AiConversation`, `AiMessage`

A conversation is workspace-scoped. A message stores `Role`, `Content`, `CitationsJson`,
`IsInsufficientEvidence`, `ModelName`, and token counts. `IsInsufficientEvidence` is
persisted so a refusal is visible in history rather than silently dropped.

### `AiExecution`

An audit row per provider call: `Purpose`, `ProviderName`, `ModelName`, `DataRoute`, `Status`,
token counts, `DurationMs`, `Error`, timestamps. This is how you prove which route served a
request.

### `AiProposal`

A model-suggested change awaiting human acceptance. Nothing an AI proposes is applied
automatically.

---

## 10. System

### `ProcessingJob`, `ProcessingJobStep`

`ProcessingJob` carries `JobType`, `Title`, `Status`, `ProgressPercent`, `CurrentStage`,
`RetryCount`, `FailureReason`, `CancellationRequested`, `RelatedEntityId`, and timestamps.
Steps are created up front so the monitor can show the whole plan before work begins.

### `AppSetting`, `AuditLog`

Key/value settings, and an append-only audit trail with `Category`, `Action`, `Detail`,
`WorkspaceId`.

## 11. Indexing decisions

| Index | Reason |
| --- | --- |
| `ChunkTerm(WorkspaceId, Term)` | Lexical lookup filters by workspace then term |
| `ChunkTerm(DocumentChunkId)` | Rebuild and delete by chunk |
| `ChunkEmbedding(WorkspaceId, Dimensions)` | Vector scan filters both |
| `DocumentChunk(DocumentId, ChunkIndex)` | Ordered chunk reads |
| `ProcessingJob(WorkspaceId, CreatedAtUtc)` | Monitor list ordering |
| `ResearchTimelineEvent(WorkspaceId, CreatedAtUtc)` | Timeline ordering |
| `Claim(WorkspaceId, Status)` | Claims overview filtering |

## 12. Migration policy

- `EnsureCreated()` is never used.
- Every schema change is a migration under
  `src/PersonalResearchLab.Infrastructure/Persistence/Migrations`.
- The initial migration is `20261121113337_InitialCreate` (42 tables).
- `AppDbContextFactory` exists so `dotnet ef` can build the model without booting the web
  host. Always pass both `--project` and `--startup-project` pointing at Infrastructure.
